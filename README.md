# heroes_student_task

## Реализованные алгоритмы

1. **`GeneratePresetImpl`: Генерация пресета армии компьютера**
    - Использован жадный алгоритм на основе коэффициента эффективности юнита: `(2 * атака / стоимость) + (здоровье / стоимость)`.
    - Ограничения:
        - Не более 11 юнитов одного типа.
        - Суммарная стоимость юнитов ≤ `maxPoints`.
    - Алгоритмическая сложность:
        - Сортировка юнитов по эффективности: O(n log n), где n — число типов юнитов.
        - Подбор количества юнитов для каждого типа: O(n).
        - Итоговая сложность: **O(n log n + n) ≈ O(n)**.
        - Генерация позиций для юнитов и их перемешивание: O(W * H), где W — ширина карты, H — высота карты. W и H фиксированы → константная сложность.

2. **`SimulateBattleImpl`: Симуляция боя**
    - Симуляция состоит из нескольких шагов на каждом раунде
    - Юниты ходят по убыванию силы атаки.
    - После каждого хода проверяется живы ли юниты.
   Алгоритмическая сложность:
      - Каждый раунд: 
      1) сбор юнитов - O(m),
      2) их сортировка по атаке O(m log m),
      3) проходка по всем юнитам для совершения атаки - O(m) где m — количество юнитов на доске.
      4) Итого на один раунд O(m) + O(m) + O(m log m) + O(m) ≈ O(m log m),
         - Всего до O(n * m) ходов, где n — число раундов.
         - Итоговая сложность: **O(n * m log m)**.

3. **`SuitableForAttackUnitsFinderImpl`: Выбор целей для атаки**
    - Проходит по рядам армии и выбирает ближайший юнит в направлении противника.
    - Алгоритмическая сложность: O(n), где n — общее число юнитов в армии.

4. **`UnitTargetPathFinderImpl`: Поиск кратчайшего пути**
    - Используется поиск в ширину (BFS) по всем соседним клеткам (8 направлений, включая диагонали),
    - Каждая клетка посещается не более одного раза,
    - Для восстановления пути сохраняется карта fromCoordsWithEdges, которая связывает текущую клетку с предыдущей,
    - Алгоритмическая сложность:
        - Размер поля: WIDTH × HEIGHT = W × H,
        - Каждый узел (клетка) посещается максимум один раз, 
        - Проверка соседей — фиксированное количество (8),
        - Итоговая сложность O(W × H) по времени,
        - Теоретически для A* с приоритетной очередью можно достичь сложности O(W × H × log(W × H)), что учитывает эвристику минимизации стоимости пути, но текущая реализация BFS эффективнее по асимптотике, хотя может давать менее «реалистичный» путь для диагональных перемещений.
